### Decouple the paired launcher before deleting the app

Add `cpp/gateway/conformance/oracle-revision.txt` containing `$legacy`. Update `conformance/run.sh` to use the pinned checkout only for Bun, its locks and historical launcher. Remove the full-tree equality guard between the candidate and oracle and replace it with independent commit/tree, clean candidate and trusted compiled package checks. `--source` in `conformance/run.py` already means the Bun source, while `--package` identifies native. Build the package from the candidate's committed source, verify the archive SHA-256 and `VERSION` commit/tree, and seal it on a qualified Linux ARM64 host. In the alternate benchmark build path, pass the candidate source to `bench/request_path/{build,package}.py`; these tools currently accept `--source` separately from the comparison runner. Keep the bench helper hash and record the identities of the Python smoke helpers if they are loaded from the oracle worktree.

`bench/request_path/run.py::identities_for` requires both sides to use identical native KV provenance. Make the oracle binding from the verified and sealed candidate package, using its `native/kv/{native-kv.node,native-kv.provenance.json}` and independently attested provenance SHA-256. Use `oracle/tools/native-kv/inputs.json` for the oracle binding and require it to byte-compare with the packaged Linux inputs. A changed addon pin needs a separately qualified cross-generation comparison policy. An independently rebuilt provenance can differ due to its build log. Editing the expected provenance hash or relaxing verification to force a pass would lose artifact custody.

For example, with `$package` the sealed release and `$binding` the resulting private JSON binding, the existing isolated runner can take the two independent roots directly. `bun` below is the absolute verified Bun 1.4.0 path.

```bash
root=$(git rev-parse --show-toplevel)
candidate=$(git rev-parse HEAD)
candidate_tree=$(git rev-parse 'HEAD^{tree}')
oracle="$scratch/oracle"
bench="$root/cpp/gateway/bench/request_path"
run=$(mktemp -d "$scratch/paired.XXXXXXXX")
mkdir "$run"/{home,tmp}
cp "$bench/isolated.sh" "$run/isolated.sh"
ln -s "$root/cpp/gateway/conformance/run.py" "$run/run.py"
cmp "$oracle/tools/native-kv/inputs.json" "$package/native/kv/inputs.json"
env -i PATH=/usr/local/bin:/usr/bin:/bin HOME="$run/home" TMPDIR="$run/tmp" LC_ALL=C.UTF-8 \
  timeout -k 10s 180s bash "$run/isolated.sh" --bench "$bench" --benchmark-revision "$candidate" \
  --source "$oracle" --source-revision "$legacy" --suite-revision "$candidate" --suite-tree "$candidate_tree" \
  --bun "$bun" --binding "$binding" --package "$package" --out "$run/output"
```

Also run `python3 -B cpp/gateway/conformance/compare_test.py` with the empty environment. The prior integrated run reported 184 passes and two shared expectation failures, `chat-invalid-role` and `responses-invalid-tool-type`, both HTTP 200 with dispatch where the suite requires HTTP 400 with zero dispatch. Preserve both assertions. Track source fixes separately for any clean paired acceptance. Historical failures and their exact evidence remain visible during dependency removal.
