# Native gateway security limits

Input budgets are defined in [`uos/rt/limits.hpp`](../include/uos/rt/limits.hpp). Client, upstream and stored inputs also retain their smaller route or protocol limits. Limits apply to counts or sizes at the stated stage. For example, Fetch measures an SSE line in decoded UTF-8 bytes before a provider turns it into events or JSON.

The acceptance tests below are registered existing binaries with additional boundary cases. The ARM64 run records the tested commit, tree, commands and outcomes. [Run findings](findings/cppgw-input-limits-20261119.md)

## Service-manager confinement

This opt-in mode is weaker than Landlock. The filesystem boundary comes from the service manager before launch. The gateway checks read-only system mounts and the sealed release, the home masks and common home secret paths, the non-root identity, empty capability sets and `NoNewPrivileges`. It installs its usual thread-synchronized seccomp filter, including child process and executable launch denial. The Antigravity CLI profile requires Landlock.

The unit masks `/home`, `/root` and `/run/user` and allows writes to the dedicated state tree. Unix permissions still govern reads of visible host files outside those masks. Place private data in protected locations, including home directories on custom paths. The gateway applies no Landlock filesystem allowlist, device `ioctl` restrictions or Unix socket and signal scoping in this mode.

The gateway applies no outbound TCP port restriction in this mode. The unit limits socket families to IPv4, IPv6 and Unix sockets. On hosts with systemd IP filtering, `IPAddressDeny=multicast` blocks multicast while leaving unicast DNS and provider HTTPS available. The IP rule operates on addresses. [Raspberry Pi setup](RASPBERRY-PI.md#start-under-systemd-without-landlock)

## Antigravity CLI

An exact `UOS_GATEWAY_ENABLE_ANTIGRAVITY=1` and a validated CLI installation allow process creation and execution for the whole gateway. Seccomp applies the exception to every gateway thread. Landlock's direct execute grants are limited to the canonical `agy` and ARM64 dynamic loader files. The loader can open compatible ELF files from the gateway's readable paths. A second Landlock ruleset narrows the CLI's view to specific host inputs, its private CLI state and its own workspace. The CLI state and workspace remain readable and writable to support the CLI. [Operator setup and residual risk](RUNTIME.md#enable-the-gemini-subscription)

Gemini CLI prompts are capped at 8 MiB. The gateway enforces a 120-second child deadline. It reads stdout and stderr alongside stdin, with a 16 MiB stdout cap from `kJsonDocumentBytes`, a 4 MiB cap per JSON event and a smaller 128 KiB stderr cap. An exceeded output budget or a cancelled request closes all child pipes and terminates and reaps the process. [Gemini transport](../src/provider/gemini.cpp)

For fixed-length Chat requests, the gateway uses its normal authenticated error response for a declared body above 16 MiB. The transport refuses the payload and closes the connection after the response. [Loopback fixture](../tests/serve_delivery_http_test.cpp)

## Regular expressions

Matching counts libregexp interrupt callbacks so identical inputs get the same work allowance on hosts with different speeds. The allowance grows with the original subject byte length so linear searches have room to scan more text.

Libregexp calls the interrupt hook after each 10,000 backtracking or loop polls within a search. One allowance covers all searches in a matching operation, including global match, replace and split. Execution interrupts at `min(kRegexMaxPolls, basePolls + floor(subjectBytes / subjectBytesPerPoll))`. The hard ceiling is 4,096 callbacks. The application allowances apply to exact source and flag pairs.

| Pattern | Allowance constant | Base polls | Subject bytes per poll |
| --- | --- | ---: | ---: |
| Generic | `kRegexWorkBudget` | 64 | 500 |
| Image reference | `kImageRegexWorkBudget` | 16 | 1,250 |
| Compaction | `kCompactionRegexWorkBudget` | 4 | 1,250 |
| SSE framing | `kSseRegexWorkBudget` | 8 | 680 |
| Supervisor credential key | `kSupervisorRegexWorkBudget` | 16 | 30 |
| Stored base64 validator | `kBase64RegexWorkBudget` | 16 | 625 |

The generic caps are `kRegexPatternBytes` (4 KiB) before UTF-8 or CESU-8 adaptation and `kRegexSubjectBytes` (1 MiB) before UTF-16 preparation. The encoded pattern can grow by half and subject preparation uses at most two bytes of storage per input byte. The supervisor credential-key pattern uses the ordinary subject cap. The fixed large ASCII image data-URL and stored-base64 validators and base64 alphabet substitutions use linear operations under their existing encoded-byte ceilings.

The engine exposes a compile stack check and a match interrupt hook. Compilation keeps the stack and allocation guards and a five-minute wall-clock backstop. Matching keeps a five-minute cooperative backstop at the interrupt hook and between short searches. Each backstop has its own `RangeError` message, and invalid patterns still raise `SyntaxError`. [Counts, calibration and verification](findings/cppgw-regex-budget-20261120.md) · [Engine hooks](../src/rt/regex_tables.cpp)
