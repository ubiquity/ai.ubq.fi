# Arch Linux ARM cutover checklist

- [ ] **Select and seal the candidate.** Build the Linux ARM64 archive with `packaging/portable/build.sh` or download the matching release artifact and `SHA256SUMS`. Run `sha256sum -c SHA256SUMS` and confirm the expected commit in `VERSION`. On the target, check ARM64, the loader and libraries, and Landlock and seccomp support. Seal into a new immutable release directory on that host and retain the two values printed by the sealer. The Arch host is **UNVERIFIED**. [Release instructions](RELEASES.md)
- [ ] **Prepare copied state.** Use a consistent stopped backup of the marked `.data/kv-bun.sqlite3` and retain the original and any WAL required for recovery. Put the copy in a separate canonical state root. Set the state root and `.data` to mode `0700`, the database and launch manifest to `0600`, and hand custody to the approved service user. Check marker, keys, revisions, expiry and representative typed values on the copy. Keep the existing service as the production writer. A copy of live state and its value readback are **UNVERIFIED** here. [Side-by-side state preparation](SIDE-BY-SIDE.md#2-prepare-isolated-state-and-render-the-unit) · [Runtime state contract](RUNTIME.md#launch-and-state)
- [ ] **Run side by side for a week.** Render a separate unit from `ops/uos-gateway-native.service`. Select the sealed release, copied state and a free loopback port other than 7999 or 8000 in the private launch manifest. Set `EnvironmentFile=` to the approved operator file and verify the rendered unit with `systemd-analyze verify`. Follow the same-host follower procedure below when using shared subscription logins. Check loopback `GET /health` for HTTP 200 and `status: "available"` and compare the identity fields and headers. Monitor the native journal, memory, latency, errors, delivery and settled quota. Use the existing observation runbook's public-read replay and conduct authenticated inference only within the owner's approved access and probe budget. The unit, operator environment and live observation are **UNVERIFIED**. [Draft service](../ops/uos-gateway-native.service) · [Observation and health checks](SIDE-BY-SIDE.md)
- [ ] **Switch after acceptance.** Obtain the owner's approval and applicable Sentinel reader acceptance. Save the old unit, immutable release and Caddy configuration. Under the deployment lock, drain both writers and prepare the native unit with the latest stopped authoritative state. Check its loopback health, exact Git SHA and `vps-<full-sha>` in the body and headers. The current portable build leaves the runtime SHA at `unknown`, so production identity requires a separately qualified release. After the owner-approved Caddy upstream switch, verify authenticated inference directly from the Mac to the VPS and check public `/health`. The switch and client acceptance are **UNVERIFIED**. [Owner cutover policy](SIDE-BY-SIDE.md#6-owner-cutover-decision)
- [ ] **Rehearse rollback.** Close candidate ingress, drain and stop the native service, and preserve its latest stopped database and WAL under the lock. Select the prior compatible release, bind it to that state, and verify that it can read the latest writes before restoring the Caddy upstream. Recheck direct authenticated inference and public health. A previous runtime using the legacy codec needs the archived offline conversion and its verified rollback receipt. Keep ingress closed if latest-state recovery is unproved. Rollback on the target is **UNVERIFIED**. [Release rollback](RELEASES.md#roll-back) · [Recovery policy](SIDE-BY-SIDE.md#6-owner-cutover-decision)

## Running side by side on one host

1. Keep production as the leader. Put the candidate's initial stopped-consistent copy of production state in a separate owner-private state directory and select a different loopback port. Add `UOS_GATEWAY_UPSTREAM_AUTH_FOLLOWER=1` to **only the candidate's** approved `EnvironmentFile=` before starting it. The leader owns subscription renewal. The follower disables Antigravity even if its opt-in is set.
2. Check the follower's loopback `GET /health`. Confirm `upstream_auth.follower` is `true`. `upstream_auth.earliest_access_token_expires_in_ms` is the time to the earliest known Codex expiry, `0` for a known expired token, or `null` when expiry is unavailable. Codex starts requiring renewal in the last two minutes of a JWT's lifetime and can also reject a bearer early. Look for `upstream_auth_follower_stale` in the journal if inference changes accounts or reports a credential error.
3. To update the follower after a leader refresh, stop and drain the follower and retain a private backup of its state. Under the approved state lock, take a private copy of the leader's drained, checkpointed `.data/kv-bun.sqlite3` and place it at `.data/kv-bun.sqlite3` under a separate, canonical snapshot directory. Resume the leader after taking the copy. Both databases must use the `bun-jsc-v1` marker and be free of SQLite `-wal`, `-shm` and `-journal` sidecars. Both state roots and their `.data` directories must be owned by the follower service user with mode `0700`, and the databases must be mode `0600`. If a WAL is present, preserve it with its database and obtain a clean checkpoint before making the import copy. Use the existing offline conversion procedure first if the leader's backup uses the legacy codec. [Runtime state contract](RUNTIME.md#launch-and-state)
4. As the follower service user, with the approved runtime environment, run the sealed release's launcher against the follower's launch manifest and the leader snapshot. Substitute the three absolute paths.

   ```sh
   UOS_GATEWAY_UPSTREAM_AUTH_FOLLOWER=1 \
     /absolute/path/to/release/ops/launch-native.sh /absolute/path/to/follower-launch.json \
     --import-codex-auth-from /absolute/path/to/leader-snapshot
   ```

   The command imports newer credentials for matching account IDs after an account-bound, read-only Codex usage check. It preserves follower-only accounts, slot order, quotas, API keys and other KV records. It prints an account count. A rejected or expired replacement aborts the update. After success, restart the follower with the switch still set and recheck its health.
5. **Remove `UOS_GATEWAY_UPSTREAM_AUTH_FOLLOWER` before the candidate becomes the only gateway.** First stop the leader and prepare the candidate with the latest authoritative state under the approved cutover procedure. Start the sole gateway with renewal enabled and run the approved health and authenticated inference checks.
