# Arch Linux ARM gateway cutover and rollback

This checklist is for the service owner. Keep the existing Bun release, launch configuration and Caddy upstream available until native client acceptance and rollback rehearsal are complete. Use the existing POSIX `.data/deploy.lock` for an approved production switch or rollback. [Side-by-side runbook](SIDE-BY-SIDE.md) · [Existing VPS operations](https://github.com/ubiquity/ai.ubq.fi/blob/2b23fb6837e2b5c0dc9ffa50771f52d322dd413a/ops/README.md)

## Prepare the release and rehearsal

- [ ] **Target host, UNVERIFIED.** Confirm Arch Linux ARM reports `aarch64` and glibc 2.36 or newer. Query the active Landlock ABI as documented in the release guide. The default service needs ABI 8 or higher and seccomp thread synchronization. Check the target's systemd, cgroup v2, IP and socket-bind filtering, and memory, CPU and disk headroom. [Release prerequisites](RELEASES.md#install-on-arch-linux-arm-or-raspberry-pi-os) · [Host checks](SIDE-BY-SIDE.md#1-qualify-the-package-and-host)
- [ ] **Package.** Download the Linux ARM64 workflow artifact for the approved full SHA or run `bash cpp/gateway/packaging/portable/build.sh /absolute/output/uos-gateway-linux-arm64.tar.gz` from that committed checkout. Check `sha256sum -c SHA256SUMS` against the trusted artifact receipt before extraction. Compare `VERSION` with the approved SHA, then run the archive's `seal.py` on Arch into a new release directory. Save the resulting package root, manifest hash and native KV provenance hash. Arch installation and sealing are **UNVERIFIED** on the qualification runner. [Build, checksum and seal commands](RELEASES.md)
- [ ] **Separate loopback service, UNVERIFIED.** Render the existing `ops/side-by-side/uos-gateway-side-by-side.service.in` with a dedicated account, separate home and state, an administrator-owned immutable package and an unused loopback port such as 18080. Keep the Bun listener and Caddy route as they are. Use the existing private launch manifest and check the rendered unit with `systemd-analyze verify --recursive-errors=one "$unit_file"`. Prove the effective network and bind restrictions on the host before starting it. The observation unit uses a sparse, credential-free environment. For the production unit, review `ops/uos-gateway-native.service` and supply the operator-owned settings via `EnvironmentFile=`, including `DENO_TIMELINE=production` and `DENO_DEPLOY_BUILD_ID=vps-<full-sha>`. The launcher reads its supplied environment and performs no implicit `.env` discovery. [Unit setup and controls](SIDE-BY-SIDE.md#2-prepare-isolated-state-and-render-the-unit) · [Production unit draft](../ops/uos-gateway-native.service)
- [ ] **Synthetic smoke.** Begin with the runbook's new marked synthetic store. On the shadow listener check `GET /health`, `HEAD /health`, `GET /openapi.json` and an HTTP 401 from credential-free `GET /health/providers`. Verify the health SHA and deployment identity in the response body and headers against the selected launch. Use `ops/side-by-side/replay.sh` in dry-run mode before `--run` and limit it to the runbook's public reads. Run the sealed-package mock acceptance for auth, inference, streaming, shutdown and durable readback. Arch systemd and Caddy integration remain **UNVERIFIED**. [Health and replay](SIDE-BY-SIDE.md#3-start-and-check-the-observation-service) · [Mock acceptance](../tests/production_smoke/README.md)
- [ ] **Production release identity gate, FAILED in Linux ARM64 qualification.** The portable package binds the source commit in `VERSION` and the sealed build profile. The executable reports `unknown` for the Git SHA in the health body and header, including when `DENO_DEPLOY_BUILD_ID` supplies the expected deployment ID. Stop before handling live state. The approved production artifact must report the full source SHA and `vps-<full-sha>` in both places. [Qualification result](findings/cppgw-final-20261119.md#isolated-side-by-side)
- [ ] **Stopped-copy rehearsal, LIVE DATA READ, UNVERIFIED.** Obtain explicit approval to handle the live store. Under the deployment lock, drain and stop its writer, then preserve a consistent private backup of the marked `.data/kv-bun.sqlite3` and account for its WAL. Leave the original Deno/V8 `.data/kv.sqlite3` in its existing custody. Before pointing native at any production state, use a separate owner-private **copy** of the stopped Bun database. Reopen the original with Bun for continued service after the copy is secured. Run native on the isolated rehearsal port with the copy and with egress blocked. Check raw keys, revisions, absolute expiry and representative typed values. Rehearse clean shutdown and prove Bun can reopen that latest native-written rehearsal copy. Keep identities and checksums in private receipts. [Stopped-state procedure](SIDE-BY-SIDE.md#6-owner-cutover-decision) · [Legacy storage recovery](https://github.com/ubiquity/ai.ubq.fi/blob/2b23fb6837e2b5c0dc9ffa50771f52d322dd413a/ops/README.md#data-migration-and-recovery)

The marked Bun/JSC format is shared only to the extent demonstrated by the KV fixtures. They cover the SQLite schema and ordered keys, revisions and expiry, typed-value round trips, sparse arrays and cyclic graph identity for the recorded inputs. Accept the stopped production copy and its reopen separately. [Bun/C++ durable interop](../tests/kv_durable_interop_test.cpp) · [SQLite KV](../tests/rt/kv_sqlite_test.cpp) · [Sparse arrays](../tests/rt/kv_jsc_sparse_test.cpp) · [JSC graph decoding](../tests/rt/kv_jsc_deserialize_test.cpp) · [Conversion](../tests/kv_runtime_conversion_test.cpp)

## Switch the service

- [ ] **LIVE DATA AND INGRESS, UNVERIFIED.** Approve the window, the accepted package, credential custody and refresh ownership, live probe budget, monitoring thresholds and rollback target. Include the standalone Sentinel reader acceptance where applicable. Save the old Caddy config and retain the proxied A record and hostname-specific Cloudflare Worker exclusion. [Owner decision and stop limits](SIDE-BY-SIDE.md#6-owner-cutover-decision)
- [ ] **LIVE DATA WRITE, UNVERIFIED.** Under the deployment lock, drain and stop Bun. Preserve the latest stopped database with its WAL disposition and verify it against the rehearsed procedure. Put the latest marked state under the approved native service's private state root and start only the reviewed native production unit. Keep a single writer. Confirm systemd and socket ownership, loopback `GET /health`, and the exact full Git SHA and `vps-<full-sha>` in `release.git_sha`, `release.deployment_id`, `x-uos-git-sha` and `x-uos-deployment-id`. [Launch and state contract](RUNTIME.md#launch-and-offline-tools) · [Monitoring](SIDE-BY-SIDE.md#3-start-and-check-the-observation-service)
- [ ] **LIVE INGRESS, UNVERIFIED.** Validate and switch Caddy to the approved native loopback upstream during the window. Verify direct Mac-to-VPS authenticated inference and the exact release identity, then check public `https://ai.ubq.fi/health`. Monitor latency, errors, interrupted delivery, quota settlement and resource use against the agreed thresholds. Trigger rollback on a failed identity, client or durability check. [VPS acceptance](https://github.com/ubiquity/ai.ubq.fi/blob/2b23fb6837e2b5c0dc9ffa50771f52d322dd413a/ops/README.md#dns-and-tls) · [Monitoring runbook](SIDE-BY-SIDE.md#3-start-and-check-the-observation-service)

## Roll back

- [ ] **LIVE DATA AND INGRESS, UNVERIFIED.** Under the same deployment lock, close ingress to native, stop the native unit via SIGTERM, verify drain and preserve the **latest** stopped native-written database and any WAL. Prove the approved Bun release reopens that state before adopting it. For a legacy Deno rollback after Bun writes, use the pinned offline helper to reverse-convert the latest stopped Bun source to a new Deno destination and verify the private receipt and supported legacy profile. Keep ingress closed while latest-state recovery is unproved. [Rollback procedure](SIDE-BY-SIDE.md#6-owner-cutover-decision) · [Offline tools](RUNTIME.md#launch-and-offline-tools)
- [ ] **LIVE INGRESS, UNVERIFIED.** Restore the approved Bun release selector and launch the rollback unit on the recovered state. Confirm loopback health identity, restore the saved Caddy upstream, verify authorized direct Mac-to-VPS inference and check public health. Restore DNS only if it changed at cutover. Retain the latest-state, release and verification receipts. [Existing VPS recovery](https://github.com/ubiquity/ai.ubq.fi/blob/2b23fb6837e2b5c0dc9ffa50771f52d322dd413a/ops/README.md#data-migration-and-recovery)
