# Native runtime and uninstalled package

This is the native VPS candidate described by contractv7, source claimv8 and launch decisionv9. It has not been deployed or accepted for production. Compiler, complete-suite, sanitizer, smoke, restart, performance and genuine native-artifact receipts are separate gates; a build, package inspection or health response does not replace them. macOS remains an audit target and the Raspberry Pi OS is unknown.

The primary configuration uses GCC16.1, Boost1.92 and direct host OpenSSL3.6.5, SQLite3.54.0, zlib1.3.2, Brotli1.2.0, Zstd1.5.7 and ICU78.3. Clang23 with libstdc++ is the separate second compiler. SQLite, gzip and fetch decompression use installed C declarations and direct symbol addresses under `UOS_GATEWAY_NATIVE_LIBRARIES`. Only the explicit existing `setZlibLibraryForTest` override retains its loader-failure seam; ordinary native inference has no automatic dynamic-library fallback. The retained GCC12 SDK comparison keeps its original shims and coroutine constraints. It is not a native release runtime dependency.

`tools/runtime-manifest.py` reads ELF metadata without executing an application or loader. A package records each executable hash, interpreter, direct `DT_NEEDED` names, transitive canonical host-library paths and hashes, required GLIBC/GLIBCXX/CXXABI versions and permitted system-only DSO runpaths. Executable RPATH/RUNPATH and missing host libraries are rejected. Shared libraries stay on the host rather than being bundled from the comparison SDK. The emitted `runtime-closure.json`, not nominal compiler versions, is the exact closure receipt. Host-library updates require rebuilding/requalifying the package when a recorded hash changes.

`tools/package.py` accepts explicit build/profile, native-KV directory/inputs/provenance hash, permissions directory and new output-directory arguments. Output must be a new directory under this worktree's `.data`. It never installs, downloads, compiles or starts the gateway. It verifies successful native-KV provenance against frozen `@deno/kv`0.14.0/source9fe65cc inputs, hashes, actual ARM64 ELF and Node-API registration; permission artifacts must be real hashed ARM64 ELF. Test fixture byte strings are not positive native-artifact inputs. Missing or corrupt inputs refuse publication and preserve a partial directory for diagnosis if copying already began.

The package layout is `bin/{uos-gateway,uos-kv-convert,uos-kv-proof}`, `static/**`, `native/kv/{native-kv.node,native-kv.provenance.json,inputs.json}`, `native/permissions/{linux-arm64.node,manifest.json}`, `runtime/launch-schema.json`, `build-profile.json`, `runtime-closure.json`, `operator-closure.json`, `package.json`, `manifest.sha256`, `README.md` and `ops/**`. Every regular file except the hash manifest itself appears once in a sorted SHA256 manifest. Content has no generated wall-clock field, file/directory modes are fixed and timestamps are normalized to epoch0. Identical binary/source/artifact/profile inputs must produce identical manifest bytes in separate output directories; reproducibility is established only by an executed two-pass receipt. The draft launcher uses only `/bin/sh` builtins and `/usr/bin/env`; its separate operator closure records those host programs and dependencies without adding them to the native application's dependency set. Python/readelf are package-construction tools, not gateway runtime dependencies.

The real gateway executable accepts exactly `--runtime-manifest <absolute-path>`. There is no default source-checkout or development-port fallback. The closed JSON schema is `runtime/launch-schema.json`: required fields are `schema:"uos-gateway-launch-v1"`, canonical `packageRoot`, canonical private `stateRoot`, lowercase `packageManifestSha256`, lowercase `nativeKvProvenanceSha256`, `hostname:"127.0.0.1"` and integer `port`. Candidate startup refuses7999/8000. The manifest is an owner-private regular file, not a symlink or hard link. Both stateRoot and its pre-existing `.data` directory must be canonical and owner-private; immutable package and mutable state roots must be disjoint.

Startup verifies the manifest hash, every listed package file, absence of unbound/symlink/non-regular package entries, executing binary location, host-library closure, package identity, native-KV artifact and provenance, and Linux permissions manifest/artifact before state or listener effects. It then applies real Landlock ABI8+ filesystem thread synchronization and seccomp process thread synchronization. Package and host runtime data are readable; only stateRoot/.data is writable. Unsupported enforcement fails closed. There is no JavaScript permission facade and subprocess execution is denied. C++ cannot undo reads or descriptors created before enforcement, so the outer sparse environment and reviewed native executable remain part of the launch boundary.

After validation/enforcement, cwd becomes stateRoot, `SQLITE_TMPDIR` is explicitly set to that same private `.data`, and immutable static resources use packageRoot. `src/static.cpp` otherwise retains cwd behavior for original module tests. Native-KV preparation supplies explicit packaged inputs so compile-time `__FILE__` development bootstrap paths are never selected by this entrypoint. The linked `rt::SqliteKv` opens the actual `.data/kv-bun.sqlite3`, verifies the Bun/JSC marker before adoption, initializes the shared handle, then enters the real authenticated application callbacks. Normal launch requires an existing private database; no implicit conversion or legacy `.data/kv.sqlite3` adoption occurs. The source serve lifecycle drains requests, closes optional telemetry and closes KV after SIGTERM/SIGINT; durable accounting and reopened-state acceptance still require actual smoke evidence.

The only optional manifest field is `fixture:{syntheticOrigin:"http://127.0.0.1:<assigned-port>"}`. It requires a non-deploy runtime, gatewayport0, a real no-outbound network namespace, private task state and a loopback scripted upstream. `DENO_TIMELINE=production` is permitted inside these fences so the fixture exercises ordinary authentication instead of the source's legacy local-hostname bypass; deployment markers remain forbidden. The fixed DeepSeek completion URL maps to `/chat/completions`, Codex maps to `/codex`, and live WebSocket sideband maps to `/live`. The real transport rejects all unmapped fetch destinations, including redirected requests; provider request schemas and authentication are unchanged. Routing ownership lasts through the full serve lifetime. An initial fixture requires an empty `.data`; after all immutable and OS checks it exclusively writes a0600 binding marker. Reopen requires that exact owner-private marker binding schema, package-manifest hash, stateRoot and syntheticOrigin. Markerless nonempty state is refused. This provides no authority to read production state.

The binary performs no automatic dotenv discovery and reads the existing environment contract. Configuration includes `DENO_TIMELINE`, deployment identity markers, `UOS_AI_TOKEN`, `DENO_DEPLOY_TOKEN`, `CODEX_AUTH_JSON_B64`, existing native-home selectors and provider-specific options; no new credential variable is introduced. Tests use an explicit sparse environment with isolated HOME/TMPDIR and synthetic tokens only. Standard runtime reads include canonical host libraries, TLS trust, resolver/hosts/localtime data, random devices and `/proc/self`, matching the Linux launcher's required OS surface. The draft operator environment-file behavior remains a documented difference from Bun's explicit repository-root dotenv loader and requires separate cutover review.

This inventory is from literal reads and defining constants; existing injected environment-reader interfaces can receive their caller's map, and OpenSSL retains its own standard trust-store environment behavior. None of these names grants filesystem or provider authority by itself. The C++ fetch client retains its documented HTTP/1.1-only/no-proxy limits, buffered-body chunking difference and non-identical gzip output; real provider transport, long soak, power loss and complete stopped-copy value decoding remain unproved. A cutover must validate a consistent stopped copy with the C++ reader and must never load two SQLite implementations against one file in one process.

Fresh isolated Bun1.4.0/SQLite3.53.2 and the actual shared SQLite3.54.0 observations match REAL text rendering, six large-number hex forms, concat/octet_length and schema-first NOTADB. The `sqlite3` CLI embeds a separate build and is not the linked-library compile-option oracle. Actual shared-library DQS_DML/DQS_DDL are1/1, matching Bun; no DQS override is needed. Host maximum expression depth10000 differs from Bun1000; the native binding applies a per-connection1000 limit after independent before/after controls and retains the exact error regression. SDK expected literals remain unchanged in the version-marked test branches. Other compile-option and compression-byte differences are not erased by the library version number alone.

Before cutover, supply genuine offline native artifacts/provenance, run the complete exact-source native/Clang/sanitizer gates, produce reproducibility and startup-refusal receipts, prove same-binary authenticated loopback requests and durable restart/accounting/shutdown, reconcile the existing codec and immutable-release ownership, obtain external Sentinel-reader acceptance where applicable, and secure separately authorized production/client acceptance. No service/unit installation, restart, proxy change, production database access, real provider request, remote Mac/Pi access or Git write is part of this runtime work.
