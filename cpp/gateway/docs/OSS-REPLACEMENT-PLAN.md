# C++ gateway open-source replacement plan

The gateway adopts mature libraries for generic parsing and encoding one component at a time. The accepted Assignment 2 baseline records 441 passing targets and 5,023 passing cases. Its saved package is the release control. The post-baseline tree with simdjson parsing and simdutf encoding has a focused native build and component parity receipts. Full suite, package, smoke and integrated performance qualification are in progress. [Runtime contract](RUNTIME.md) [Performance receipt policy](PERFORMANCE.md)

## Scope and decisions

The inventory covers `src/rt`, `include/uos/rt`, their HTTP adapters in `src/runtime/http*.cpp` and `include/uos/runtime/http*.hpp`, the adjacent `#http` WebSocket loader, and the generic CBOR, ASN.1 and X.509/CRL slices in `src/auth/passkeys.cpp`. Keep gateway routing, authorization, quota, paid ledgers, provider behavior, credentials, persistence authority and the WebAuthn verification policy at their existing boundaries. HTTP receipt code is counted because it shares files with the wire parser and remains necessary. Attestation-format decisions, trust anchors, revocation fetch/cache policy, and challenge/session handling stay with passkeys. The SSE protocol framer in `src/responses_stream.cpp` is an HTTP and regex consumer. [Port manifest](../PORT-MANIFEST.json) [Runtime contract](RUNTIME.md) [Existing open stages](OPEN-STAGES.md)

**REPLACE** means the library owns the implemented generic operation after qualification and the gateway keeps the required compatibility adapter. **FAST-PATH** means the library handles a proven input class and the current path preserves exact behavior elsewhere. **KEEP** means retain the current implementation or existing library adapter. The rank puts qualified and hot-path work first, then likely removed lines relative to migration risk. Approve replacements on required behavior, adapter size and measured caller costs. Record size-specific penalties and process resource changes alongside aggregate gains.

**LOC** means physical lines, including comments, blanks and generated rows. The disjoint file/range ledger reflects the current `json.cpp` and `json_simdjson.hpp` and the published Base64 encoder. The regex row includes 3,388 generated Unicode table lines, leaving 2,930 other physical lines. Migration figures estimate first-party lines after excluding upstream source. KEEP rows retain their current LOC and have zero planned deletions.

### JSON parse and serialization

The published `UOS_GATEWAY_SIMDJSON` profile uses simdjson 5.2.0 DOM and returns ordinary, independently mutable `boost::json::value` storage. The input scratch and tape are thread-local, with a 2 MiB input ceiling and a 32-container exploration bound. It falls back directly to the original JavaScript-exact parser on a decline, including library errors, duplicate or special keys, potential negative zero, unproved numeric edge cases and WTF-8 inputs the library cannot accept. Profiles without that macro use the existing Boost 1.92 adapter where available and the same original fallback. Keep the exact `jsonParse` and `jsonParseBody` contracts, including ordered members, key identity, number bits, JSC error class/message/position and complete input consumption. [JSON entry points](../src/rt/json.cpp#L1339) [DOM adapter](../src/rt/json_simdjson.hpp) [Value conventions](rt/values.md)
