# C++ gateway open-source replacement plan

The planned library replacements are integrated into the Linux ARM64 release. First-party production C++ went
from **191,176** lines at `55afcc8b13b2ddd10747355745da19e5264f7b76` to **179,288** lines in the integrated code.
The original estimates below apply to a narrower runtime and protocol census. The report gives the measured file
groups, final suite totals and package receipts. [Final integration](findings/cppgw-integrate-f2-20261118.md)

## Policy and scope

The owner's November 17 v37 rule makes the pinned library the reference for generic runtime behavior. Replace the generic implementation, retain the smallest adapter that the gateway needs and remove the Bun-quirk fallback. Keep the gateway's wire, authentication, authorization, validation, persistence, resource limits, delivery and settlement contracts. Stricter generic input handling is acceptable when these contracts pass. Preserve all application outcomes and cover the supported platforms. Record generic test expectation changes with one example per component in `docs/DEVIATIONS-FROM-BUN.md`, and add a bounded robustness harness for each new library entry point.

The scope is `src/rt`, `include/uos/rt`, the HTTP adapters, the `#http` WebSocket loader, and the protocol codec slices in passkeys. HTTP session and request-body code is included in the census because it shares the parser's and writer's files. Application routing, auth/credential decisions, quota and paid ledgers, attestation trust/cache policy, and stopped-state storage custody remain with their current owners. The JSC and typed-value readers preserve sparse entries, references and cycles. Stopped-state migration and rollback acceptance remain open.
