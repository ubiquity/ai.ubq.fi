# Native owner source composition

This unit is not activated by a source merge or CI. It requires an accepted native service RELEASE artifact, exact private control-owner and two-home custody bindings, Worker receipt and explicit operational authorization. The private passive probe or debug artifact is not a service release.

Prepare a complete immutable payload at a new accepted SHA under .data/releases/<sha>/native-owner; refuse existing SHA collisions. The fixed inventory is Rust bin/uos-native and three TypeScript launcher/validator files. Manifest v1 binds source/tree/Cargo-lock/build-receipt hashes, Linux ARM64 target, normal release profile (opt s, test false, debug assertions false, fixture disabled), and every payload file hash/size. Do not relabel a test profile or download/build/install at startup.

Private .data/native-owner/config.json is caller-owned mode0600 nonsecret data. Its closed schema requires release SHA/tree/manifest hash, expected control key ID/owner ID/epoch/key fingerprint/owner revision, accepted Worker origin/source/namespace/object/receipt hash and exactly two distinct home/owner mappings. These are actual operator receipt inputs, not generated defaults or identity proof by themselves. The independent operator verifies installed rows and current file/account/source custody.

Long-lived secret resides only in repository-root .env as UOS_NATIVE_CARRIER. Native origin is https://origin.ubq.fi; capabilities supervisor_read/owner_renewal/access_publish and both mappings must match private config. The launcher computes SHA256 of the decoded canonical32byte key and compares the expected control fingerprint. Native v2 stdin excludes carrier capabilities, binds127.0.0.1:7990, uses dedicated .data/native-owner/replay/nonces.sqlite3 and targets ONE accepted reverse Worker origin. Key is passed only in closed stdin, not child environment/arguments/logs. Provider keys are excluded from child environment.

The .data/native-owner-current selector resolves once; never reuse .data/current. Unit and same-basename99 drop-in are linked from ops into exact /etc/systemd/system/uos-native-owner.service* paths only after approval. Global overrides remain unchanged. Verify real child cgroup caps after startup, not only systemctl properties. PrivateTmp stays false so actual Codex sockets remain visible. Don't restrict DNS/TCP before native preconnect.

Restart follows authoritative native failure, not a timer. Rust's loss path bounds its local drain; process exit is not a positive global drain acknowledgement, and ordinary TERM has no graceful Rust signal handler. Hold admission/reconcile before planned stop. Keep latest replay DB/operation rows on rollback; never replay refresh or restore stale credentials/nonces. Existing Codex daemons are never restarted by this unit.

Existing origin site may add only exact POST /v1/native/rpc,/v1/native/follow,/v1/native/control before app selectors, preserving path/body/headers to127.0.0.1:7990. Do not use handle_path or flush_interval-1: Caddy2.11.7 disables backend cancellation in that mode. SSE uses automatic flushing. No new hostname/DNS/public port. Reverse /uos/native/renewal-authority and /uos/native/publication are Worker paths, not native ingress.

Operational acceptance is separate: release/ABI/process-denial receipts, installed control tuple, actual two homes, scoped proxy proof, real caps, closed reverse channel→old process settlement→new process→usable signed control, original unknown operation never repeating refresh, and requested authenticated inference/upstream/client evidence. Source fixtures claim none of that live acceptance.

The immutable .uos-native-owner-build.json is required and hash-bound by the manifest. Its accepted build-producer facts bind exact source/tree/lock/binary hash, target uos-native/bin and actual normal release profile/feature facts. It is trusted operator evidence, not self-minting authority. Keep the original Cargo JSON/feature graph with the external release receipt. Native-live capabilities are deliberately unsupported and non-drainable in this composition; enabling them would block positive drain acceptance.
