# Rust verification scope, descriptor v1

The M48 implementation contract is version 4, SHA-256 `52851426051923578d1c0714a6ef4e521820b8b4ec5af2a53c9af073b9c5cd82`. This document describes source preparation; deterministic and real CLI acceptance remain pending until source freeze and the assigned compiler/evidence slot. It changes no release profile, Rust source, Cargo manifest/lock, baseline, workflow, deployment, credential or provider behavior.

The shared descriptor uses only pinned Bun built-ins and `/usr/bin/git`; it requires no Cargo metadata, npm dependency install or tool preparation to select CI jobs. Immutable base/head snapshots retain raw input hashes and exact identities. Supplied paths are unioned with the actual Git delta, tracked edits and relevant untracked inputs. Dirty input snapshots cannot establish narrow root-manifest proof, and the executable CLI rejects them before compiler execution.

| Input                                                                                   | Selected action                                                                                                                                  |
| --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Proven local member/path extraction and local lock records                              | Union of old/new affected normal/build consumers plus their dev test consumers; a new helper is native only when every consumer is proven native |
| Production Rust source                                                                  | Reverse normal/build closure and direct dev test consumers; private and public edits use the same correctness closure                            |
| Explicit tests/examples/benches/runtime fixtures                                        | Owner's native all-target Clippy and package tests; no propagation through production consumers                                                  |
| Literal compiled fixture or root favicon                                                | Compiled owner and production consumers; compiled ownership overrides a documentation extension                                                  |
| Worker static files, entrypoint, configuration, package graph or build launcher         | Actual new-identity shipping Worker build                                                                                                        |
| Unknown root/feature/profile/config/build-script/lock/input semantics or policy tooling | Complete relevant stages with a stated reason, or an input-validation error                                                                      |
| Decoded-equal local metadata only                                                       | Explicit no-compiler selection with raw hashes retained and formatting still required                                                            |

Local edges resolve inherited dependencies, renamed aliases and paths. Lock comparisons use full name/version/source identities and checksums; ambiguous references, duplicate identities and missing local inventories are errors. Optional edges remain included, the reviewed native normal-target exclusion stays narrow, and build/proc-macro host edges remain included. Native-only packages entering the shipping Worker production/host closure are rejected.

The include candidate scanner is deliberately incomplete. It skips supported strings/comments, binds literal candidates that exist, and records uncertain forms instead of rejecting valid source based on a guessed parse. Uncertainty selects complete stages. The current `CARGO_MANIFEST_DIR` concatenation in the routing test-support catalog has an explicit input entry bound to its audited source hash; source drift invalidates that entry. This supplements the mandatory existing all-source Rust structural parser and does not replace it.

`scripts/rust-verify-plan.ts` owns command planning extracted from the formerly 992-line verifier. Selected Clippy commands retain complete successful JSON requirements. Native fixtures retain their real supported OS isolation, emitted-artifact checks and serial execution. Exact `exact-rust` and `exact-worker` namespaces and `guardRustTarget` remain unchanged. Complete acceptance still selects all packages and an actual Worker build; no prior PR receipt is retroactively narrowed.

Acceptance requires the existing owner/verifier/quality/test-scope contracts plus the new input/scope fixtures, changed-file ESLint and supported formatting, strict TypeScript and early size/diff gates. After the final tree freezes, real native-only root-manifest/lock and Worker-reachable fixtures must run through the actual CLI with source, owner, profile, complete Clippy and artifact receipts. No benchmark was run and no compiler-speed or cache-saving result is claimed.

Root `.cargo/config` and `.cargo/config.toml` additions, edits and deletions select complete relevant stages. Ignored local Cargo configurations invalidate immutable-source proof. Literal test/example/bench/support-module inputs have separate test ownership; CI consults the descriptor for external TS, JSON and markdown paths before deciding that they are unrelated to Rust. The real admin contract's include of `src/handler/index.ts` selects admin's native tests while preserving unrelated Worker production inputs. Linked include paths and dirty or untracked external input bytes cannot establish immutable source.
