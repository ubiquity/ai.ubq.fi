# Rust Worker real-provider e2e on the VPS, second run (2026-11-05)

This run repeats `rust-worker-vps-provider-e2e-2026-11-05.md` (the "previous run") against the current `rust-migration` tip. Its purpose is to confirm five fixes merged since then:

1. Chat Completions usage recorded in ledger rows and the quota projection (`302bbc2`).
2. `provider_request_id` populated for buffered DeepSeek chat from the body id, `x-uos-provider-request-id` echoed, and OpenRouter header ids (`302bbc2`).
3. Per-request latency: TTFB close to the Worker's own latency, no serialization of concurrent requests, fast warm `/v1/models` (`18fcaf8`).
4. A client abort mid-stream recorded as interrupted (`b335371`).
5. Native early SSE headers for a Codex `x-codex-turn-metadata` turn, and `response.created` + `response.failed` frames for a failure after the early commit (`18a7de4`).

The method, binding profile and safety rules were the same as in the previous run. Owner authorization (2026-11-05): inference against cheap models with low reasoning, `max_output_tokens` at most 32 (at most 200 for the abort case). No secret value was printed, logged, written to a file or committed. No Codex or OAuth credential was bound, read or refreshed. The production gateway, its `.env`, `.data`, service and checkout were not modified; the `.env` was only sourced, read-only, in a test subshell. Nothing was deployed.

## Findings

1. **Client abort is still not recorded as interrupted (fix 4 not confirmed).** In two attempts, the client aborted after 4 frames. The Worker closed each ledger row at about the abort time (1,129 ms and 1,453 ms), so it saw the end of the stream. However, it wrote no `/admin/errors` row, its ledger row is an ordinary `status_code 200`, and `replay-captures` reports `no_capture_record`. The `b335371` change preserves the reader and body facts and marks delivery as `Interrupted` "on a platform client abort". Either the local workerd, with `request_signal_passthrough`, does not surface the disconnect as a platform client abort, or the interrupted terminal is not persisted to the error log for Chat streams. This run cannot tell which. Whether the upstream DeepSeek request was cancelled also remains unproven, as before.
2. **OpenRouter Chat Completions stream ends without a usage chunk or `data: [DONE]`.** This was reproduced twice. The client received exactly two chunks (content, then `finish_reason:"stop"`) and a clean end of body. The ledger had null tokens, and the quota projection did not count it. `302bbc2` says OpenRouter chat streams now request `stream_options.include_usage`, and OpenRouter normally sends a usage chunk and then `[DONE]`. Either the Worker stops relaying after the finish chunk, or the upstream did not send them. Without outbound observation this run cannot tell which. The DeepSeek chat stream did end with usage and `[DONE]`. OpenRouter chat streams were not exercised in the previous run, so it is not known whether this is a regression. Treat it as a wire-compatibility defect until proven otherwise: OpenAI clients expect `[DONE]`.
3. **OpenRouter provider ids are not captured.** Neither the non-stream nor the stream OpenRouter requests returned `x-uos-provider-request-id` or stored a ledger id. Either OpenRouter did not send any header in the `providerRequestIdFromResponse` set, or the read failed. The body fallback applies only to DeepSeek and Cerebras by design. Streamed rows from every provider have a null id.
4. The Cerebras production key still returns 402 `payment_required`, so the buffered `gpt-oss-120b` replay is still unobserved against the real API.
5. A native request whose routing fails (unknown model) is answered as JSON 503 before any commit. That matches the gate design (commit only after a successful dispatch gate), but it means "invalid model" is not a way to reach the late-failure path. An upstream rejection after the dispatch gate (row 12) is.
6. For a routing failure, the ledger row names `provider:"chatgpt_codex"` while `/admin/errors` names `provider:"gateway"`, although Codex is not configured. This was only observed; it may mislead an operator.
7. The pass-through of non-OpenAI fields is unchanged from the previous run's finding 5: DeepSeek `reasoning_content` and `prompt_cache_*_tokens`, and OpenRouter `cost`, `is_byok`, `cost_details` and chunk `provider`/`native_finish_reason`.
